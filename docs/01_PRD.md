# 카페 판매·손익·재고 관리 제품 요구사항 문서(PRD)

- 작성일: 2026-10-12
- 상태: 1차 범위 A 확정. 사용 환경 및 운영 기준은 추가 협의 필요.
- PRD는 만들 제품의 목적, 핵심 기능, 완료 조건을 정리한 문서다.
- 이번 문서는 계산식, 화면 디자인, 기술 선택, 상세 동작, 코드를 정하지 않는다.

## 1. 제품 목적과 핵심 흐름

카페 운영자가 판매와 비용을 기록한 뒤, 어떤 메뉴가 얼마나 남기는지와 선택 기간의 손익, 재료 잔량을 함께 확인한다. 흩어진 기록을 연결해 매일의 운영 판단을 돕는 것이 목적이다.

**판매 기록 입력 → 메뉴별 수익성 확인 → 기간 손익 및 재료 잔량 확인**

예를 들어 오늘 카페라테 판매를 기록하고, 해당 메뉴의 수익성을 확인한 다음 우유 입고·폐기·실제 재고 기록과 함께 잔량을 점검한다. 이는 이용 흐름의 예시이며 계산 방법을 확정한 것은 아니다.

## 2. 자료에서 확인한 사실

확인 자료는 `data/데이터설명.md`, `data/매장운영데이터.xlsx`, `data/매장운영데이터.json`이다. 엑셀의 시트·열·기록 수와 JSON의 항목·기록 수·기간을 확인했다. 전체 셀의 일대일 일치나 모든 금액의 정확성까지 검증한 것은 아니다.

### 2.1 자료의 성격과 기간

- 매장명은 프렙 카페이며, 실제 거래 내역이 아닌 직접 구성한 가상 매장 샘플이다.
- 기록 기간은 2025-07-01부터 2026-09-18 마감까지다. 영업달력만 2026-09-30까지 있다.
- 금액은 원, 부가세 제외 기준이다. 재료 수량 단위는 g·ml·개다.
- 엑셀과 JSON은 같은 기록의 두 형식으로 설명되어 있다. 두 파일을 별도 거래처럼 합치면 안 된다.
- JSON의 `settings`는 비어 있다. 앞으로의 운영 정책이 합의되어 있다는 근거는 없다.

### 2.2 포함된 기록

| 자료 | 기록 수 | 확인한 주요 내용 |
| --- | ---: | --- |
| 공급사 | 3 | 공급사 식별번호와 이름 |
| 재료 | 11 | 기준단위, 구매용량, 최초 구매가격, 납기·안전재고 영업일수, 공급사 |
| 메뉴 | 8 | 이름, 판매기준가, 분류, 레시피 버전 |
| 레시피 | 22 | 메뉴 1개당 재료 사용량, 단위, 적용 판매채널 |
| 재료가격이력 | 33 | 적용시작일별 구매가격과 구매용량 |
| 영업달력 | 457 | 영업 여부, 마감 여부, 날씨, 메모 |
| 판매기록 | 6,112 | 일자·메뉴·채널별 수량, 당시 단가, 할인, 순매출, 결제수수료, 당시 개당 원가 |
| 초기재고 | 11 | 2025-07-01 영업 시작 전 재료 수량 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 |
| 월비용계획 | 120 | 2025-07부터 2026-09까지 월별 비용항목·금액 |
| 비용기록 | 3,560 | 월 비용을 날짜별로 나누어 기록한 비용 |
| 자료정보 | 10 | 매장명, 출처, 통화, 기간 등 |

엑셀에는 위 기록 시트 외에 설명용 `데이터안내` 시트도 있다.

판매채널은 매장·포장이다. 판매 한 줄은 주문 한 건이 아니라 **하루의 특정 메뉴·채널 판매 집계**다. 판매ID·재고 기록ID·비용ID의 중복은 확인되지 않았으며, 판매의 일자·메뉴·채널 조합도 중복되지 않았다.

비용은 임차료, 인건비, 사업주 부담 보험료, 수도광열비, 관리비, 광고비, 소모품·청소비, 통신·소프트웨어의 8개 항목이다. 모든 비용기록의 배분기준은 `월비용 일할 배분`이다. 실제 현금 지급일이나 영수증별 지출을 나타낸다는 근거는 없다.

### 2.3 기획할 때 주의할 점

| 주의점 | 제품에 주는 의미 |
| --- | --- |
| 월비용계획과 비용기록은 같은 비용의 월·일 표현이다. | 서로 별도의 지출로 더하지 않아야 한다. |
| 원가·수수료·배분 결과는 과거 기록이다. | 앞으로 입력할 기록의 기준이나 수익성 분류 기준으로 자동 확정하지 않는다. |
| 판매기준가와 판매 당시 단가가 구분되어 있다. | 현재 기준가로 과거 판매를 바꿔 해석하지 않아야 한다. |
| 재료 구매가격은 구매용량 전체의 금액이다. | 메뉴 1개당 사용량이나 단위당 원가와 혼동하지 않아야 한다. |
| 적용채널이 빈 레시피는 모든 채널, 포장은 포장 판매만 적용된다. | 포장재 사용과 원가를 매장 판매에도 동일하게 적용하지 않아야 한다. |
| 입고는 양수, 폐기는 음수이고 실사조정은 양수·음수 모두 존재한다. | 증감수량과 실제로 센 수량을 구분해야 한다. |
| 초기재고·레시피·재고기록이 따로 있다. | 입고·폐기 기록만으로 판매 후 잔량이 확인되는 것은 아니다. |
| 미마감 날짜와 휴무일이 존재한다. | 미입력, 미마감, 휴무, 판매 0을 구분해야 한다. |
| 빈칸은 해당 없음 또는 미입력이다. | 빈칸을 무조건 0으로 바꾸지 않아야 한다. |
| 연도별 기록은 일부 기간만 포함한다. | 일부 기간 실적을 완전한 연간 실적으로 표현하지 않아야 한다. |
| 납기·안전재고 일수는 영업일 기준이다. | 나중에 발주량을 추천할 때 단순한 달력 일수와 혼동하지 않아야 한다. |

## 3. 사용자 요청과 확정 사항

### 3.1 전체 제품에서 원하는 기능

판매·비용 기록 직접 입력·수정·삭제, 엑셀 양식 내려받기와 가져오기, 메뉴 수익성, 기간별 실적과 예상 손익, 재료 입고·폐기·실제 재고 기록, 부족 재료와 발주량 참고, 일·주·월·분기·반기·연간 조회, 저장·백업·복원이다.

### 3.2 이번 대화에서 확정한 사항

- **1차 범위는 A: 직접 기록과 재고 연결을 우선한다.** 사용자가 A를 선택했다.
- 1차는 판매·비용 직접 입력·수정·삭제, 재료 입고·폐기·실제 재고 기록, 수익성·손익·잔량 확인, 일·월 조회, 저장·백업·복원에 집중한다.
- 엑셀 양식·가져오기, 예상 손익, 발주량 추천, 주·분기·반기·연간 조회는 2차로 옮긴다.
- 기획·화면 설계·개발·검사·배포를 모두 포함해 4시간 안에 가능한 작은 첫 버전을 목표로 한다.

## 4. 1차 구현할 핵심 기능(MVP)

MVP는 실제로 핵심 흐름을 사용해 볼 수 있는 첫 최소 버전이다. 아래 내용은 기능의 목적과 완료 조건이며 화면 구성이나 처리 절차를 지정하지 않는다.

| 번호 | 기능 | 사용자가 할 수 있어야 하는 일 |
| --- | --- | --- |
| M01 | 제공 자료로 시작 | 제공된 메뉴·재료·레시피·가격·초기재고·판매·비용·재고·영업달력 기록을 바탕으로 핵심 흐름을 사용한다. 엑셀과 JSON을 중복 기록으로 포함하지 않는다. |
| M02 | 판매 기록 관리 | 날짜·메뉴·매장/포장 채널별 판매를 직접 입력·수정·삭제한다. 판매 수량·당시 판매금액·할인 등 수익성 판단에 필요한 정보를 기록할 수 있다. |
| M03 | 비용 기록 관리 | 날짜·비용항목·금액을 직접 입력·수정·삭제하고 선택 기간의 비용을 확인한다. 제공 자료가 날짜별 배분 비용임을 구분한다. |
| M04 | 메뉴 수익성 확인 | 선택한 일 또는 월의 메뉴별 판매 실적과 수익성을 확인한다. 판단에 포함된 비용 범위와 자료 기준을 이해할 수 있다. |
| M05 | 기간 실적·손익 확인 | 일·월 단위로 판매·비용·손익을 함께 확인한다. 기록된 실적과 아직 마감하지 않은 기간을 구분한다. |
| M06 | 재고 기록과 잔량 확인 | 입고·폐기·실제 재고를 직접 기록하고 재료별 잔량과 확인 기준일을 확인한다. 기록에 따른 잔량과 실제로 센 수량을 구분한다. |
| M07 | 판매와 재고 연결 | 판매 변경의 영향을 메뉴 수익성·기간 손익·재료 잔량에서 확인한다. 포장 전용 재료의 적용 차이를 반영할 수 있어야 한다. |
| M08 | 저장·백업·복원 | 기록을 보관해 다시 사용하고, 별도 백업으로 기록을 되살린다. 판매·비용·재고와 결과 해석에 필요한 기준 자료를 함께 보전한다. |

### 4.1 범위를 작게 유지하기 위한 제안

- 첫 대상은 제공 자료의 메뉴 8개와 재료 11개로 제안한다. 메뉴·레시피·재료·공급사를 자유롭게 추가·변경하는 관리 기능은 2차로 제안한다.
- 수익성은 운영 판단에 필요한 결과 확인을 우선한다. 좋음·나쁨 자동 분류, 목표 달성 등급, 추천 메뉴 선정은 2차로 제안한다.
- 잔량 확인은 1차 핵심이다. 자동 부족 판정과 발주 추천은 기준 합의 후 2차로 제안한다. 1차에서는 사용자가 잔량을 보고 재료 부족을 점검한다.
- 일·월 조회를 먼저 제공한다. 여러 기간 비교, 복잡한 분석 보고서, 출력용 보고서는 2차로 제안한다.
- 단일 매장, 한 명이 주로 사용하는 간단한 첫 버전을 추천한다. **사용자 수와 사용 장소는 아직 미정**이며, 이 제안은 확정 사항이 아니다.
- 제공 자료로 시작하는 기능과 사용자가 파일을 직접 가져오는 기능은 구분한다. 1차에 엑셀/JSON 범용 가져오기 기능을 포함한다는 뜻은 아니다.

## 5. 2차 구현할 확장 기능

| 기능 | 사용자 가치 | 2차로 제안하는 이유 |
| --- | --- | --- |
| 엑셀 양식 내려받기·판매/비용 가져오기 | 여러 기록을 한 번에 입력한다. | 중복·누락·잘못된 값 처리까지 고려해야 하므로 직접 입력 흐름 검증 후 확장한다. |
| 주·분기·반기·연간 조회 및 기간 비교 | 더 긴 운영 추세를 확인한다. | 1차는 일·월 핵심 확인에 집중한다. 기간 경계와 일부 기간 표시를 별도로 정해야 한다. |
| 예상 손익 | 아직 끝나지 않은 기간의 결과를 참고한다. | 전망에 사용할 기간·자료·가정이 미정이다. |
| 부족 재료 자동 판정·발주량 추천 | 언제 무엇을 얼마나 사야 할지 참고한다. | 필요한 재고 수준, 판매 예상, 납기, 구매 묶음 등에 대한 판단 기준이 미정이다. |
| 메뉴·재료·레시피·가격이력 관리 | 메뉴와 구매 조건의 변화를 기록한다. | 과거 판매와 재고에 미치는 영향을 다루는 범위가 커진다. |
| 수익성 분류·추천·목표 비교 | 판매할 메뉴와 개선 대상을 판단한다. | 좋은 수익성의 기준과 비용 포함 범위를 먼저 합의해야 한다. |
| 월비용계획 편집·계획 대비 실적 | 계획과 기록의 차이를 확인한다. | 현재 자료의 배분 비용과 앞으로의 실제 비용 관계를 정해야 한다. |
| 여러 사람·여러 기기 공유 | 직원과 사장이 같은 기록을 함께 관리한다. | 실제 필요 여부를 확인한 뒤 접근 범위와 함께 확장한다. |

2차 목록은 확장 제안이다. 세부 범위와 순서를 모두 확정한 것은 아니다.

| 마감과 누락의 의미 | 미정 | 판매가 없는 날과 기록을 아직 입력하지 않은 날을 구분해야 한다. |
| 저장·백업·복원 범위 | 기능 포함 확정, 운영 방식 미정 | 어디에서 다시 쓰고, 어떤 범위까지 되살려야 하는지 확인해야 한다. |
| 부족 기준·발주량·예상 손익 | 2차, 기준 미정 | 자료에 납기와 안전재고 일수가 있어도 추천 정책은 합의되지 않았다. |
| 주·분기·반기·연간 기간 기준 | 2차, 기준 미정 | 주 시작일과 집계할 연도 기준 등을 이후 정해야 한다. |

이번 PRD에서는 계산식이나 상세 처리 방법을 정하지 않는다. 개발에 필요한 계산 기준은 후속 단계에서 별도로 합의한다. 질문은 **한 번에 하나씩**, 생활 속 예시와 선택지, 추천 이유를 함께 제시한다.

다음은 1차 범위 A에 대한 시간 배분 제안이며 완료 보장이 아니다. 제공 자료를 활용하고, 사용자·사용 환경을 작게 합의한다는 조건으로 계획한다. 여러 사람의 동시 사용이나 기기 간 공유가 필요하면 4시간 범위를 다시 조정한다.

## 8. 1차 완료 조건

검사에서는 다음 사용자 결과를 확인한다. 계산 기준이 미정인 항목은 후속 합의가 있어야 정확한 결과 검사가 가능하다.

1. 제공 자료를 한 번의 기록으로 사용하며, 매장·포장과 기준단위를 구분한다.
2. 판매를 입력·수정·삭제한 뒤 해당 일·월의 메뉴 수익성, 손익, 재료 잔량에서 영향을 확인한다.
3. 비용을 입력·수정·삭제한 뒤 해당 기간 결과에서 영향을 확인한다. 월 계획과 일별 비용을 이중으로 포함하지 않는다.
4. 재료 입고·폐기·실제 재고를 기록하고, 기준일과 함께 잔량을 확인한다. 실제로 센 수량과 증감수량의 의미를 혼동하지 않는다.
5. 과거 기록, 미마감 기간, 빈칸, 0을 구분하며 자료가 없는 결과를 확정된 실적으로 제시하지 않는다.
6. 다시 사용해도 저장된 기록을 확인하고, 백업에서 판매·비용·재고 및 필요한 기준 자료를 복원해 핵심 흐름을 사용할 수 있다.
7. 합의한 배포 환경에서 판매 입력부터 수익성·손익·잔량 확인까지 사용할 수 있다.
