# 카페 판매·손익·재고 관리 기능 요구사항 문서(FRD)

- 작성일: 2026-10-12
- 상태: 기능 범위와 메뉴 수익성의 비용 범위 확정. 나머지 처리·계산 기준은 제안 또는 미정.
- FRD는 사용자의 입력과 행동에 대해 프로그램이 무엇을 처리하고 어떤 결과를 보여주는지 정리한 문서다.
- 대상: 판매 입력 → 메뉴 수익성 → 기간 손익·재료 잔량을 확인하는 1차 버전.
- 이 문서만으로 기능의 목적·입력·처리·화면 결과·파일 결과·오류 상황을 파악할 수 있도록 작성했다. 미정인 정책은 구현 전에 합의해야 하며, 문서에 예시가 있다는 이유로 확정하지 않는다.

`design/_4/screen.png`는 이미지로 읽을 수 없었다. 대시보드 기능은 HTML 내용을 기준으로 확인했으며 PNG와의 시각적 일치 여부는 확인하지 못했다. 다른 네 화면은 이미지와 HTML을 함께 확인했다. 시안은 제품의 완성된 동작이나 정책 합의의 증거가 아니다.

### 1.2 상태 표시의 의미

- **확정:** PRD 필수 기능 또는 이번 대화에서 사용자가 선택한 내용.
- **제안:** 필수 기능을 구현하기 위한 처리·계산 방법 후보. 아직 승인된 정책이 아니다.
- **미정:** 사용자 선택이 필요한 내용. 임의 기본값으로 처리하지 않는다.
- **1차 제외:** PRD의 2차 기능 또는 사용자가 1차에 추가하지 않기로 한 시안 기능.

**아래 기능의 존재와 목적은 확정이지만, 별도로 확정이라고 적지 않은 입력 제한·처리 순서·계산·오류 대응은 제안이다.** 이는 새 기능을 승인 없이 추가하기 위한 목록이 아니라, 기존 필수 기능을 어떻게 작동시킬지 검토할 초안이다.

### 1.3 확정된 결정

1. PRD의 A 범위 유지: 직접 판매·비용 관리, 재고 직접 기록, 메뉴 수익성·기간 손익·잔량, 일·월 조회, 저장·백업·복원.
2. PRD와 시안의 차이는 PRD 범위를 우선한다. 자동 부족 경고·일마감 승인·세무 증빙 검증·클라우드 동기화·CSV/엑셀 보고서·전체 초기화는 1차에서 제외한다.
3. **메뉴에서 남는 금액은 할인 후 매출에서 재료비·포장비·결제수수료를 뺀 금액으로 한다.** 임차료·인건비 등 매장 운영비는 메뉴에 나누어 붙이지 않고 기간 전체 손익에서 별도로 뺀다.

사용자 수·사용 장소는 이전 질문에 답이 없어 여전히 미정이다. 특정 저장 기술, 공유 방식, 로그인·권한을 확정하지 않는다.

## 2. 프로그램에서 다루는 기록

- 제공 자료는 프렙 카페의 **가상 샘플**이다. 판매·비용·재고는 2025-07-01~2026-09-18 마감 기록, 영업달력은 2026-09-30까지다.
- 기준 자료: 공급사 3개, 재료 11개, 메뉴 8개, 레시피 22줄, 재료가격이력 33줄, 초기재고 11줄, 영업달력 457일, 월비용계획 120줄.
- 운영 기록: 판매 6,112줄, 재고 1,515줄, 비용 3,560줄. 엑셀과 JSON은 같은 기록이므로 두 번 합치지 않는다.
- 판매 한 줄은 날짜·메뉴·매장/포장 채널별 집계다. 주문 건수·고객 수·객단가를 계산할 근거가 아니다.
- 금액은 원·부가세 제외다. 세금 신고나 부가세 계산 기능은 포함하지 않는다.
- 재료 단위는 g·ml·개다. 구매가격은 구매용량 전체의 가격이며, 판매에 기록된 식재료원가·포장원가는 메뉴 1개당 당시 금액이다.
- 비용기록은 월 비용을 날짜별로 나눈 값이다. 실제 지급 영수증이나 현금 흐름으로 표현하지 않는다. 월 계획을 같은 기간 비용에 다시 더하지 않는다.
- 실제로 센 수량과 재고를 늘리거나 줄인 수량은 다른 기록이다. 초기재고의 기준은 첫날 영업 시작 전이다.

## 5. 기능별 입력·처리·결과·예외

각 기능에서 '보관 기록'은 프로그램에 저장되는 내용이다. 매번 별도 파일을 내려받는다는 뜻은 아니다. 다운로드 파일은 F15에서만 필수이며 다른 기능에는 별도 보고서 파일을 추가하지 않는다.

### F01. 제공 자료로 시작하기 — M01

- **사용자 행동:** 처음 프로그램을 열어 제공 기록을 확인한다.
- **처리 제안:** 한 형식의 자료만 초기 기록으로 사용하고 식별번호로 메뉴·재료·레시피·판매·재고·비용을 연결한다. 이미 보관 기록이 있으면 재실행할 때 샘플을 덧붙이거나 덮어쓰지 않는다.
- **화면 결과:** 가상 샘플임을 구분하고 자료 기간·마감 기준을 표시한다. 판매·비용·재고 조회가 가능하다.
- **보관 기록:** 기준 자료와 운영 기록, 출처·기간·단위. **별도 다운로드:** 없음.
- **오류·예외 제안:** 자료 누락·읽기 실패·중복ID·없는 메뉴/재료 참조·단위 불일치가 있으면 원인을 표시하고 잘못된 자료로 정상 결과를 만들지 않는다. 기존 저장 기록이 있다면 보존한다. 최초 전체 적용과 일부 적용 중 어느 방식을 허용할지는 미정이며 전체 검사 후 적용을 추천한다.

### F02. 화면 이동과 일·월 조회 — M04·M05

- **사용자 행동:** 메뉴를 선택하거나 조회 단위를 일/월로 바꾸고 대상 날짜·월을 선택한다.
- **입력:** 조회 단위, 날짜 또는 연월. 시안의 특정 날짜는 예시다.
- **처리 제안:** 같은 선택 기간으로 판매·비용·손익을 조회한다. 재고는 기간 합계가 아니라 해당 일의 종료 시점 또는 월말/확인 가능한 기준일까지의 잔량을 조회한다.
- **화면 결과:** 선택 기간, 실제 기록이 포함된 범위, 마감/미마감/자료 없음 상태, 재고 기준일. 화면을 바꾸어도 선택 기간을 유지하는 방식 추천.
- **보관 기록·파일:** 조회만으로 거래를 변경하거나 다운로드하지 않는다. 마지막 조회 조건 보관 여부는 미정.
- **오류·예외 제안:** 잘못된 날짜는 조회하지 않고 수정 안내. 2026-09 월 조회는 18일까지의 기록임을 명시한다. 19~30일을 매출 0인 실적으로 채우지 않는다. 실제 오늘에 자료가 없으면 '자료 없음'으로 표시하며, 마지막 기록일을 몰래 오늘로 대체하지 않는다. 월말까지 재고 기록이 없으면 마지막 확인 기준일을 표시한다.

### F03. 판매 등록 — M02·M07

- **사용자 행동:** 신규 판매 등록 → 입력 → 계산 결과 확인 → 저장 및 재고 반영.
- **입력:** 날짜, 메뉴, 채널(매장/포장), 판매 수량, 판매 당시 단가, 해당 집계 전체의 할인금액. 결제수수료와 원가의 결정 방식은 미정이다. 레시피 버전은 판매 기록과 연결한다. 메모 보관은 미정.
- **처리 제안:** 입력을 검사하고 6절에 따라 순매출·개당 원가·판매 원가·메뉴에서 남는 금액·재료 사용량을 구한다. 저장 전 미리보기는 입력 결과일 뿐 확정 실적이 아니다. 저장 성공 후 한 판매 기록을 보관하고 연관 결과를 갱신한다.
- **화면 결과:** 등록된 판매 행, 메뉴 수익성, 해당 기간 손익, 해당 날짜 이후 재료 잔량. 저장 성공/실패를 명확히 표시한다.
- **보관 기록:** 판매ID, 날짜, 메뉴ID, 채널, 수량, 당시 단가, 할인, 순매출, 결제수수료, 레시피 버전, 당시 개당 식재료·포장원가. **다운로드:** 없음.
- **오류·예외 제안:** 필수 누락·음수 단가·음수 할인·수량 0 이하/소수·할인이 할인 전 매출을 초과하면 저장하지 않고 해당 입력을 안내한다. 0원 판매 허용 여부는 미정. 같은 날짜·메뉴·채널이 이미 있으면 기존 기록 수정을 안내하는 방식 추천이며 자동 합산/덮어쓰기는 미정. 레시피·가격·수수료가 없으면 해당 계산을 불가로 표시하고 임의 0을 넣지 않는다. 미래·휴무·마감 날짜 등록 정책과 재고가 음수가 될 때 저장 허용 여부는 미정.

### F04. 판매 수정 — M02·M07

- **사용자 행동:** 대상 판매를 선택 → 수정 → 저장.
- **처리 제안:** 기존 입력과 당시 원가·수수료를 확인할 수 있게 한다. 이전 판매의 효과를 제거하고 수정한 판매의 효과로 결과를 다시 구한다. 날짜·메뉴·채널 변경은 이전 대상과 새 대상 모두 갱신한다. 원가를 유지할지 다시 적용할지는 6절의 미정 사항이다.
- **화면 결과:** 판매 행, 해당 메뉴 수익성·기간 손익·재고 잔량의 변경 결과.
- **보관 기록·파일:** 같은 판매ID의 내용 변경, 별도 다운로드 없음.
- **오류·예외 제안:** F03의 검사 적용. 대상이 없거나 날짜·메뉴·채널 중복이 생기면 변경하지 않는다. 저장 실패 시 기존 판매와 재고 결과를 유지한다. 실제 재고를 센 날짜보다 이전 판매를 수정했을 때 이후 잔량 처리 정책은 미정이다.

### F05. 판매 삭제 — M02·M07

- **사용자 행동:** 대상 판매 선택 → 삭제 요청 → 대상 확인 후 삭제 확정.
- **처리 제안:** 날짜·메뉴·채널·수량을 확인한 뒤 해당 판매를 집계에서 제외한다. 그 판매에 따른 재료 사용을 다시 중복 취소하지 않도록 전체 결과를 일관되게 갱신한다.
- **화면 결과:** 판매 행 제거, 수익성·손익·잔량 갱신. 취소하면 기존 결과 유지.
- **보관 기록·파일:** 대상 삭제. 별도 다운로드 없음. 삭제 이력이나 되돌리기 기능은 새 필수 기능으로 추가하지 않는다.
- **오류·예외 제안:** 이미 없는 대상은 삭제 완료로 중복 처리하지 않는다. 저장 실패 시 원본 유지. 과거 판매 삭제와 이후 실측 재고의 관계는 정책 합의 필요.

### F06. 메뉴 수익성 조회 — M04

- **사용자 행동:** 일 또는 월을 선택하고 메뉴별 결과를 확인한다.
- **처리:** 판매를 메뉴·채널별로 모아 순매출, 식재료·포장원가, 결제수수료, 메뉴에서 남는 금액을 구한다. **메뉴 비용 범위는 확정**이다. 개당 평균·비율 계산과 표시 항목은 6절 제안.
- **화면 결과 제안:** 메뉴명, 판매수량, 순매출, 판매 원가, 결제수수료, 남는 금액·비율. 매장/포장의 차이와 기준 기간을 구분한다. '공헌이익'을 쓴다면 '임차료·인건비를 빼기 전 메뉴에서 남는 금액'으로 설명한다. '순이익'·'영업이익'과 혼용하지 않는다.
- **보관 기록·파일:** 조회 결과는 원본에서 구한다. 별도 보고서 파일 없음.
- **오류·예외 제안:** 순매출 0이면 비율은 계산 불가/해당 없음. 필요한 원가·수수료 누락 시 해당 메뉴 결과를 불완전으로 표시하고 전체 합계도 정상인 것처럼 보이지 않게 한다. 기록이 없는 메뉴와 0 판매 기록을 구분한다. 높은 수익성 등급·랭킹은 만들지 않는다.

### F07. 비용 등록 — M03

- **사용자 행동:** 비용 직접 등록 → 날짜·항목·금액 입력 → 저장.
- **입력:** 비용 귀속일(손익에 포함할 날짜), 비용항목, 금액. 발생일·지급일과 귀속일을 같은 것으로 볼지는 미정이다. 적요·증빙 방식은 미정이며 파일 첨부·세무 검증은 제외다.
- **처리 제안:** 새 비용이 기존 배분 비용을 바꾸는 것인지 별도 추가 비용인지 구분할 기준을 먼저 정한다. 합의한 기준에 따라 비용기록에 반영하고 해당 기간 손익을 갱신한다. 월비용계획을 자동으로 지출에 더하지 않는다.
- **화면 결과:** 비용 행과 해당 일·월 비용·손익. 배분 기록과 실제 지출이라는 의미가 다른 자료를 한 가지 '실제 지출'로 표시하지 않는다.
- **보관 기록:** 비용ID, 귀속일, 항목, 금액, 기록 기준. 추가 설명 보관은 미정. **다운로드:** 없음.
- **오류·예외 제안:** 날짜·항목·금액 누락, 숫자가 아닌 금액은 저장하지 않는다. 음수 비용/환급·0원 기록 허용 여부는 미정. 같은 날짜·항목이라도 별도 비용일 수 있으므로 판매처럼 무조건 중복 차단하지 않는 방식 추천. 같은 월 비용의 재입력인지 구분할 근거가 없으면 자동으로 '중복 검증 완료'라고 표시하지 않는다.

### F08. 비용 수정 / F09. 비용 삭제 — M03

- **사용자 행동:** 수정은 대상 선택 → 입력 변경 → 저장. 삭제는 대상 선택 → 확인 → 삭제 확정.
- **처리 제안:** 수정은 기존 비용의 기여분을 새 값으로 바꾸고, 삭제는 해당 비용을 집계에서 제외한다. 귀속일·항목 변경은 이전·새 기간 모두 반영한다. 취소하면 유지한다.
- **화면 결과:** 비용 목록과 해당 기간 비용·손익 갱신. 메뉴에서 남는 금액과 재료 수량에는 직접 영향을 주지 않는다.
- **보관 기록·파일:** 기존 비용ID 변경 또는 대상 삭제, 별도 다운로드 없음.
- **오류·예외 제안:** 없는 대상·입력 오류·보관 실패는 기존 내용 유지. 제공된 배분 비용을 수정/삭제해 월 계획과 차이가 생길 때 월 계획도 바꿀지 여부는 미정이며 자동 수정하지 않는 방식 추천. 시안에 직접 비용만 수정·삭제가 있어도 기존 배분 기록을 어떻게 관리할지 누락하지 않는다.

### F10. 재료 입고·폐기 기록 — M06

- **사용자 행동:** 재료의 관리 또는 입고/실사 기록 → 입고/폐기 선택 → 입력 → 저장.
- **입력 제안:** 날짜, 재료, 수량, 기준단위, 사유. 입고에는 단위원가·공급사 정보를 연결한다. 구매 묶음 수량·전체 가격으로 입력할지 기준단위 수량·단가로 입력할지는 미정.
- **처리 제안:** 사용자에게 입고량·폐기량을 모두 양수로 입력받고 내부 기록에는 입고를 양수, 폐기를 음수로 변환한다. 합의 후 적용하며, 원본 음수 폐기 자료에 다시 음수 변환하지 않는다. 재료 사용량이 아닌 입고/폐기 기록 한 건만 보관하고 해당 날짜 이후 잔량을 갱신한다.
- **화면 결과:** 변동 유형·수량·기준일과 변경 잔량. 입고 구매액을 기간 비용에 자동 추가하거나 판매 원가를 자동 변경하지 않는다. 그 정책은 별도 합의 사항이다.
- **보관 기록:** 재고 기록ID, 날짜, 재료ID, 유형, 증감수량, 단위, 사유, 해당 시 입고단위원가·공급사. **다운로드:** 없음.
- **오류·예외 제안:** 없는 재료, 단위 불일치, 수량 누락/0 이하, '개' 수량의 소수는 저장 차단을 추천한다. g·ml 소수 허용 자릿수는 미정. 폐기량이 잔량보다 많거나 과거 입고가 누락된 경우 자동으로 잔량을 0으로 맞추지 않는다. 저장 허용/차단은 미정. 입고 정보 누락은 재고 수량 확인과 원가 계산의 영향을 구분한다.

### F11. 실제 재고 기록 — M06

- **사용자 행동:** 실사조정 → 재료·기준일 선택 → 실제로 센 수량 입력 → 차이 확인 → 저장.
- **처리 제안:** 해당 기준시점의 기록 잔량과 실제 수량의 차이를 구한다. 실제 센 수량과 조정량을 함께 보관하며 판매량이나 레시피 사용량을 임의 변경하지 않는다.
- **화면 결과:** 기준시점의 기록 잔량, 실제 센 수량, 차이, 반영 후 잔량. 실사조정은 차이를 맞추는 기록이며 실제 폐기와 동일한 손실 금액으로 자동 처리하지 않는다.
- **보관 기록:** 실사조정 유형, 재료·날짜·단위·사유, 실측수량, 증감수량. **다운로드:** 없음.
- **오류·예외 제안:** 실측 0은 유효한 값으로 취급하는 방식 추천. 음수 실측·단위 불일치는 차단. 차이 0인 실사도 실측 사실을 남길지 미정. 같은 날 여러 실사, 실사 당일 판매의 전/후, 실사 이전 판매 변경 정책은 미정. 시안의 '이후 영구 누적' 문구를 합의 없이 확정하지 않는다. 증감 직접 입력 모드는 실제 수량 기록과 다른 방식이므로 허용 여부를 확인한다.

### F12. 재료 잔량 조회 및 판매 연동 — M06·M07

- **사용자 행동:** 일/월과 재료 잔량 화면을 선택한다.
- **처리 제안:** 초기재고, 기준일까지의 입고·폐기·실사조정, 같은 기간의 레시피 기반 판매 사용량으로 잔량을 구한다. 조회 월의 판매만 초기재고에서 빼지 않고 초기 기준일부터 연결한다. 실측 후 과거 변경 정책은 합의한 방식을 따른다.
- **화면 결과 제안:** 재료·단위·기준일·초기재고·누적 입고·폐기·판매 사용·실사조정·기록 잔량. 최근 실측수량은 실측 날짜와 함께 구분한다. 월간 잔량은 매일의 잔량 합계가 아니다.
- **보관 기록·파일:** 원본 기록으로 조회, 별도 다운로드 없음. 판매 사용량을 재고기록으로 추가 보관할지는 기술 설계 사항이며, 어느 방식이든 같은 판매를 두 번 차감해서는 안 된다.
- **오류·예외 제안:** 초기재고·레시피 누락은 영향 재료의 계산 불가 표시. 음수 잔량은 누락 가능성을 설명하되 0으로 숨기지 않는다. 재료 단위가 다르면 그대로 합산하지 않는다. 자동 부족 분류·안전재고 수량·발주량은 표시하지 않는다.

### F13. 기간 실적·손익 — M05

- **사용자 행동:** 대시보드에서 일/월과 날짜를 선택하거나 판매·재고 기록 화면으로 이동한다.
- **처리 제안:** 순매출, 식재료·포장원가, 결제수수료, 해당 기간 운영비를 구분해 집계하고 6절의 손익을 구한다. 메뉴 원가·수수료를 운영비에서 다시 빼지 않는다.
- **화면 결과:** 순매출, 포함 비용과 구성, 기록 기준 손익, 적용 기간·마감 상태. '추정'이면 레시피 사용량 기준이라는 뜻을 설명하며 미래 매출 전망처럼 표현하지 않는다. 재료 확인 바로가기는 F12로 이동한다.
- **보관 기록·파일:** 조회만 수행, 별도 보고서 다운로드 없음.
- **오류·예외 제안:** 일부 미마감·원가/비용 누락이면 불완전함을 표시한다. 미래 날짜는 실적 0으로 채우지 않는다. 운영비가 휴무일에도 있으면 영업여부만으로 삭제하지 않는다. 적자 금액은 그대로 표시하며 목표·등급·손익분기점은 계산하지 않는다.

### F14. 기록 보관과 다시 사용하기 — M08

- **사용자 행동:** 판매·비용·재고를 저장하고, 프로그램을 닫았다가 다시 연다.
- **처리 제안:** 거래와 기준 자료를 보관한다. 저장 성공을 확인한 기록만 저장 완료로 표시하고, 다시 열 때 보관된 기록으로 결과를 구한다. 화면에 잠깐 반영된 상태와 보관 완료 상태를 구분한다.
- **화면 결과:** 저장 상태와 재접속 후 동일한 기록·결과. 저장 장소와 다른 기기 접근 가능 여부는 사용 환경 합의 후 명시한다.
- **보관 기록·파일:** 운영 기록·기준 자료·합의된 운영 기준. 별도 다운로드는 F15. 저장 기술·위치는 미정.
- **오류·예외 제안:** 공간 부족·접근 불가·저장 실패 시 실패를 알리고 기존 기록 유지 및 입력 내용을 보존하는 방식 추천. 읽기 실패 시 샘플로 자동 덮어쓰지 않는다. 여러 창에서 동시에 수정하는 정책은 사용 환경 결정 후 정한다.

### F15. 백업 파일 받기 — M08

- **사용자 행동:** 백업 받기를 선택한다. 시안 버튼명은 'JSON 백업 받기'다.
- **처리 제안:** 저장 완료된 시점의 운영·기준 자료를 하나의 복원 가능한 파일로 만든다. JSON은 글자로 된 구조화 데이터 파일이며 전체 복원에 적합해 추천한다. 형식은 아직 미정이다.
- **파일 결과 제안:** 판매·비용·재고 기록, 메뉴·재료·공급사·레시피·가격이력·초기재고·영업달력·월비용계획, 출처·통화·기준일, 합의된 운영 기준, 백업 생성 시각과 형식 버전. 이름 예: `prep_cafe_backup_20261012_143000.json`. 다운로드 날짜와 데이터 마감일은 구분한다.
- **화면 결과:** 생성 결과, 포함 기록 수, 생성 시점. 단순 건수 요약만 있는 파일을 전체 백업이라 표시하지 않는다. 파일 생성/내려받기 요청과 사용자가 실제 보관한 사실은 구분한다.
- **오류·예외 제안:** 미저장 변경이 있으면 포함 여부를 알리고 저장 후 백업 추천. 생성·다운로드 실패는 기존 데이터 유지와 재시도 안내. 빈 운영 기록도 기준 자료와 함께 백업할 수 있는 방식 추천. 자동 백업·클라우드 전송·CSV 요약은 추가하지 않는다.

### F16. 백업 복원 — M08

- **사용자 행동:** 파일 선택 → 내용 검증 결과 확인 → 복원 시작 → 대체 범위 확인 → 실행 또는 취소.
- **처리 제안:** 확장자뿐 아니라 내용 구조·필수 항목·ID 중복·자료 간 연결·단위·버전을 검사한다. 전체 대체 방식을 추천하며 합치기 여부는 미정이다. 실제 적용이 끝난 뒤 결과를 다시 구하고 성공을 표시한다.
- **화면 결과:** 파일명, 백업 시점, 대상 매장·기간·기록 수, 현재 기록 대체 여부, 완료/실패. 메뉴·재료 수를 시안처럼 무조건 8/11로 고정 표시하지 않고 검증 내용에서 확인한다.
- **파일·보관 결과:** 선택 파일은 읽기만 한다. 성공 시 운영·기준 자료와 합의된 정책을 함께 복원한다. 원본 자료 JSON과 프로그램 백업 파일을 같은 형식이라고 가정하지 않는다.
- **오류·예외 제안:** 파일 미선택·선택 취소는 변경 없음. 빈 파일·깨진 JSON·요약 전용 파일·필수 항목 누락·중복ID·없는 재료 참조·지원하지 않는 버전은 사유를 표시하고 복원하지 않는다. 다른 매장 파일, 크기 제한, 단위/정책 불일치는 기준 미정. 실패 시 일부만 바뀌지 않게 현재 기록 전체 유지, 취소도 변경 없음. 시안의 50MB 제한은 미확정. 복원 전 현재 백업을 권장하되 자동 백업 기능을 추가한 것으로 보지 않는다.

## 6. 계산 방법

### 6.1 계산 상태와 공통 제안

메뉴 수익성의 비용 포함 범위만 확정이다. 아래 식은 그 범위를 구현하기 위한 **계산 제안**이며 새 판매의 원가·수수료·비용·실사 정책과 반올림 기준은 별도로 합의한다. 제공된 과거의 순매출·원가·수수료를 참고용 추정치로 덮어쓰지 않는 방식을 추천한다.

- 입력 금액은 원·부가세 제외 기준으로 설명한다. 부가세 포함 금액을 자동 변환하지 않는다.
- 할인은 집계 전체의 할인액으로 양수 입력을 추천한다. 시안의 음수 할인 표시와 원본의 할인 값을 혼동하지 않는다.
- 누락 값과 실제 0은 다르다. 계산에 필요한 값이 없으면 해당 계산과 의존하는 합계의 불완전함을 드러낸다.
- 계산 중간에는 가능한 원래 정밀도를 유지하고 표시할 때 반올림하는 방식을 추천한다. 금액 저장 정밀도, 수량 자릿수, 비율 표시 자릿수는 미정이다.

### 6.2 판매와 메뉴 수익성

| 계산 항목 | 방법 제안 |
| --- | --- |
| 할인 전 매출 | 판매수량 × 판매 당시 단가 |
| 순매출 | 할인 전 매출 − 집계 전체 할인금액 |
| 재료 단위당 가격 | 해당 날짜에 적용되는 구매가격 ÷ 그 가격에 대응하는 구매용량 |
| 메뉴 1개당 식재료원가 | 적용 레시피의 식재료별 사용량 × 재료 단위당 가격을 합산 |
| 메뉴 1개당 포장원가 | 적용 채널의 포장재 사용량 × 단위당 가격을 합산. 매장 판매에 포장 전용 재료를 넣지 않음 |
| 판매 원가 | 판매수량 × (당시 개당 식재료원가 + 당시 개당 포장원가) |
| 결제수수료 | 새 기록은 금액 직접 입력 또는 순매출 × 합의한 수수료율 중 선택 필요. 과거는 기록된 금액 보존 추천 |
| 메뉴에서 남는 금액 | 순매출 − 판매 원가 − 결제수수료. **포함 비용 범위 확정** |
| 남는 비율 | 메뉴에서 남는 금액 ÷ 순매출 × 100. 순매출 0이면 비율 계산하지 않음 |
| 메뉴 기간 합계 | 같은 기간·메뉴의 각 판매수량·매출·원가·수수료·남는 금액을 각각 합산 |
| 메뉴 기간 비율 | 기간 남는 금액 합계 ÷ 기간 순매출 합계 × 100. 행별 비율의 단순 평균을 사용하지 않음 |
| 개당 평균 남는 금액 | 기간 남는 금액 합계 ÷ 판매수량 합계. 수량이 0이면 계산하지 않음 |

원가 분류는 포장컵세트·디저트포장세트를 포장재로 보는 방식을 추천한다. 단순히 포장채널인 모든 재료를 포장재로 분류하지 않는다. 가격이력은 판매일 이하 적용시작일 중 가장 최근의 것을 사용하는 방식 추천. 일치하는 가격·레시피가 없으면 최초가격·현재가격·0을 임의로 넣지 않는다.

**미정:** 기존 판매의 수량·단가만 수정할 때 원가 기록을 유지할지, 판매일·메뉴·채널을 바꿀 때 원가를 다시 적용할지, 입고단가가 이후 판매원가를 바꾸는지, 새 판매수수료를 어떻게 정할지. 시안의 1.8%는 채택되지 않았다.

**가상 계산 예시:** 10개 × 5,000원 − 총 할인 2,000원 = 순매출 48,000원. 개당 식재료·포장원가 합계 1,500원, 총 수수료 800원이면 판매원가 15,000원, 남는 금액 32,200원, 비율 약 67.1%다. 이는 자료의 실제 거래나 확정된 메뉴 가격이 아니다.

### 6.3 기간 비용과 손익

| 계산 항목 | 방법 제안 |
| --- | --- |
| 기간 순매출·판매원가·수수료 | 해당 날짜 범위의 판매 기록을 각각 합산 |
| 기간 운영비 | 해당 귀속일의 비용기록 합산. 월비용계획은 별도 계획 정보이며 다시 더하지 않음 |
| 기간 총비용 | 판매원가 + 결제수수료 + 기간 운영비 |
| 기록 기준 손익 | 기간 순매출 − 기간 총비용 |
| 손익 비율 | 기록 기준 손익 ÷ 기간 순매출 × 100. 순매출 0이면 계산하지 않음 |

메뉴에서 남는 금액을 합산해 기간 운영비를 빼는 방법으로도 같은 결과가 나와야 한다. 결제수수료를 두 번 빼면 안 된다. 재료 입고 구매액과 판매 원가도 자동으로 함께 비용에 넣지 않는다.

월 계획으로 일 비용을 새로 만들 필요가 생기면 '월 금액을 그 달의 달력 일수로 나누고 반올림 차이는 마지막 날에 맞춤'을 후보로 제안한다. **1차는 제공된 일별 비용기록을 그대로 쓰는 방식을 추천**하며, 이미 있는 비용을 다시 자동 생성하지 않는다. 월 비용을 영업일로만 나눌지, 직접 비용을 추가/대체로 볼지, 폐기·실사차이를 손익에 포함할지는 미정이다. 미정 비용을 반영하지 않은 결과에는 포함하지 않은 범위를 설명한다.

손익은 기록·레시피 기준의 운영 참고값이다. 실제 현금 잔액이나 세무 신고용 확정 이익으로 표시하지 않는다. 미래 예상 손익과는 다른 기능이다.

### 6.4 판매 사용량과 재료 잔량

| 계산 항목 | 방법 제안 |
| --- | --- |
| 판매의 재료 사용량 | 판매수량 × 판매 레시피의 재료별 개당 사용량. 적용채널이 비면 모두, 포장이면 포장 판매만 포함 |
| 입고 | 해당 재료의 양수 입고수량 합산 |
| 폐기 | 해당 재료의 음수 폐기수량 합산. 원본이 음수이므로 잔량 식에서 다시 빼지 않음 |
| 실사 차이 | 실제 센 수량 − 실사 기준시점의 기록 잔량 |
| 기록 잔량 | 초기재고 + 누적 입고 + 누적 음수 폐기 + 누적 실사조정 − 누적 판매 사용량 |

예: 초기 우유 5,000ml, 입고 2,000ml, 폐기 기록 −200ml, 판매 사용 1,800ml이면 기록 잔량은 5,000ml다. 실제로 4,900ml를 셌다면 차이는 −100ml다. 이 예시는 운영 기준 선택을 대신하지 않는다.

**실측 이후 과거 수정 처리 후보:**

- A: 실사 당시 확정한 조정량을 유지하고 과거 판매 변경을 이후 잔량에도 반영한다. 단순하지만 계산된 실사일 잔량이 당시 실측수량과 달라질 수 있다.
- B: 실측수량을 그 시점의 기준으로 유지하고 이전 판매 수정에 따라 조정량을 다시 구한다. 실제로 센 잔량은 유지되지만 실사조정 기록이 달라질 수 있다.

원본에는 조정량과 실측수량이 모두 있다. 두 후보 중 어느 것도 합의되지 않았다. 같은 날은 입고·판매·폐기 후 마감 실사를 적용하는 순서를 후보로 제안하며, 여러 실사나 영업 중 실사는 별도 결정이 필요하다. 확인되지 않은 시간·순서를 만들어 넣지 않는다.

| 변경 | 메뉴 수익성 | 기간 손익 | 재료 잔량 |
| --- | --- | --- | --- |
| 판매 수량·메뉴·채널 | 변경 | 변경 | 변경 |

## 9. 2차 기능과 새 기능의 처리

PRD의 2차 목록인 엑셀 양식·가져오기, 주·분기·반기·연간 조회, 기간 비교, 미래 예상 손익, 부족 판정·발주량 추천, 기준 자료 편집, 수익성 분류·추천, 월 계획 편집, 여러 사람·기기 공유는 **1차 기능이 아니다**. 후속 FRD에서 범위·입력·계산·오류 기준을 정한다.

시안에만 있는 보고서 출력·세무 검증·POS 연동·자동 백업·리셋 등은 2차 도입도 자동 확정하지 않는다. 사용자 확인이 있을 때만 요구사항으로 추가한다. 이번 작업은 문서 작성이며 시안 파일·PRD·데이터를 수정하지 않는다.
