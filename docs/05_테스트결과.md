### 발견 및 수정

- 첫 자동 검사에서 9월 원두 기대가격에 1월 가격을 사용한 테스트 오류 3건이 있었다. 원본 9월 구매가격 24,840원/1,000g과 Python 별도 계산을 확인해 기대값을 바로잡았다. 계산 구현이 아니라 검사 기대값 오류였다.
- 브라우저 날짜 입력의 표시값과 React 상태값이 일치하지 않는 문제가 발견되었다. 날짜·월 입력의 input 이벤트 처리도 연결해 재검사했다. 수정된 날짜로 실제 저장·이동하는 것을 확인했다.
- 빈 입력에서 숫자 계산 오류가 나오지 않도록 입력 검사를 먼저 수행하고 항목 이름을 오류 문구에 포함했다.
- 큰 금액의 소수를 표시 과정에서 잃지 않도록 십진 문자열·정수 그룹 표시를 사용하고 자동 검사를 추가했다.

## 7. 성능·배포 확인 범위

- 자동 검사 환경(Node + fake-indexeddb)의 전체 샘플 측정: 백업 구역 읽기 125ms, 전체 복원 쓰기 약 1,418ms, 재료 잔량 계산 26ms. 실제 브라우저나 모든 기기의 성능 보장으로 사용하지 않는다.
- 브라우저에서는 실제 다운로드·파일 검사·전체 복원을 완료했다. 네트워크·파일 선택·도구 왕복 시간을 앱 처리시간으로 계산하지 않는다.
- 50MiB는 입력 상한 정책이다. 상한 크기 파일 전체의 성능은 아직 측정하지 않았다.
- Vercel 빌드·출력 폴더·보안 헤더 설정은 준비했다. 실제 원격 저장소·계정 연결은 없으므로 GitHub 업로드·Vercel 배포·운영 주소 검사는 미수행이다.

- 선택 메뉴에 마우스를 올릴 때 배경이 밝아져 흰 글자가 흐려지는 문제를 수정했다.
- 최종 타입 검사, 자동 검사 65개(실패 0), 배포 파일 생성 모두 통과했다.
- 실제 브라우저의 2026-09 월간 손익 6,414,712.72원, 운영비 3,798,010원 및 11개 재료 잔량이 원본 기대값과 일치했다.
- 390×844 크기에서 메뉴 선택 및 재료 잔량 요약을 확인했다. 원두 4,280g, 우유 23,180ml를 가로 표 이동 없이 확인할 수 있다. 검사 뒤 화면 크기 설정을 원래대로 되돌렸다.
- 작은 화면 증거: `.qa/epic23-mobile-preview.png`. 개발자 검사 중 앱 오류 로그는 없었다.
- 앞선 전체 백업·복원 검사 결과는 §6에 기록되어 있다. 검사용 자료는 복원으로 제거했고 원본 파일을 수정하지 않았다.
- EPIC 2·3의 로컬 기능 구현·개발자 검사는 통과 상태다. 사용자 확인은 대기이며 EPIC 완료 표시는 유지한다. EPIC 3의 GitHub 보관·Vercel 실제 배포는 별도 연결·운영 주소 확인이 남아 있다.
